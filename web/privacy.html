Privacy policy

NoiseCrypt runs entirely on your machine. It has no account, no server, no telemetry, no crash reporting and no update check, and it sends nothing to BREIZHZION or to anyone else. This page lists everything it does read, write and contact, so you can check it.

Last updated 2026-10-24. Applies to NoiseCrypt 0.7.2 and later, on Windows, macOS and Linux. Version française plus bas.

01 / What is processed

What NoiseCrypt handles, and where it goes

Everything below happens on your computer. None of it is transmitted by NoiseCrypt.

Data NoiseCrypt processes
DataWhat happens to it
The contents of the files you encrypt or decrypt Read into memory, encrypted or decrypted, and written to the output you asked for. Never stored anywhere else and never sent.
Passphrases Typed without echo, or read from the file or environment variable you name with -passphrase-file / -passphrase-env, or typed into the interface. Held in memory for the operation only. NoiseCrypt never writes a passphrase to disk or to a log, and never puts one on a command line. In the interface, your browser or password manager may offer to remember a passphrase field, as on any page: that copy, if you accept it, belongs to the browser, not to NoiseCrypt.
Your private identity (your key) Generated on your machine and stored in a file, protected by your passphrase unless you explicitly choose not to. See storage.
Other people's public identities Read from the file or text you give with -to or -from. Not copied or remembered.
File name and modification date of an encrypted file Stored inside the encrypted container, so only the recipient sees them, and restored on decryption.

02 / Local storage

Everything NoiseCrypt writes on your disk

This is the complete list. Nothing else is written, and there is no settings file, no history and no log.

Your identity

noisecrypt keygen, or the first-run screen of the interface, writes two files in a .noisecrypt folder in your home directory (%USERPROFILE%\.noisecrypt on Windows, ~/.noisecrypt on macOS and Linux):

  • identity.ncrykey: your private identity. Encrypted with your passphrase (Argon2id), unless you chose to store it unprotected, in which case anyone who can read the file has your key. Identities made by older versions may be called identity, without extension; they are used as they are and never renamed.
  • identity.ncrypub: your public identity, the part you hand out. It holds nothing secret.

The folder is deliberately not under AppData: a domain or Entra joined Windows profile can synchronise AppData to a server, and a private key should not copy itself anywhere without being asked. The environment variables NOISECRYPT_HOME and NOISECRYPT_IDENTITY move the folder or the file elsewhere.

Permissions. On macOS and Linux the folder is set to 0700 and the files to 0600. On Windows, NoiseCrypt runs icacls on the folder and on each file: inheritance is cut, and the Administrators, SYSTEM and Users groups are removed, leaving your account alone with access. This stops other ordinary accounts from reading your key; it does not stop someone who can already act as an administrator on the machine. One consequence: backup software that runs as SYSTEM may not be able to read these files, so copy your identity yourself to a safe place.

Identity in a folder you choose. keygen -out and the Windows right-click entry Create a NoiseCrypt identity here write the same two files in the folder you pointed at, and apply the same restriction to that folder, not only to the files.

Files you ask for

Every other file NoiseCrypt writes is one you asked for, at the path you gave or next to its input, and it refuses to overwrite an existing file unless you pass -force:

  • seal writes an encrypted .ncry container (by default the input name with .ncry added).
  • encode writes a .mp4 video, produced by FFmpeg.
  • open and decode write the recovered file, under the name stored in the container, in the current folder (for the right-click entry, normally the folder that holds the container).
  • simulate -keep leaves its test videos (<profile>-master.mp4, <profile>-h<height>-crf<quality>.mp4) in the folder you name.

Temporary files

Some operations need a file on disk because FFmpeg and yt-dlp read and write paths. They are created in the system temporary folder with unpredictable names and, on macOS and Linux, owner-only permissions, and they are deleted as soon as the operation ends, including when it fails: noisecrypt-dl-* (a video downloaded from an address), noisecrypt-in-* (a video given to the interface), noisecrypt-*.mp4 (a video the interface produces), noisecrypt-simulate-* (simulate without -keep), and multipart-* (a large upload received by the interface). If NoiseCrypt is killed in the middle of an operation, one of these can remain; it is safe to delete.

Windows integration

If you keep the installer option Right-click to encrypt, double-click to decrypt (it is on by default, including in a silent install), or run noisecrypt shell register, NoiseCrypt writes these keys under HKEY_CURRENT_USER\Software\Classes, for your account only: *\shell\NoiseCryptEncrypt, Directory\Background\shell\NoiseCryptIdentity, NoiseCrypt.Container and .ncry. They contain menu labels, an icon reference and the path of the program, nothing else. noisecrypt shell unregister removes them. The installer option Add NoiseCrypt to my PATH appends the program folder to your user Path variable, and uninstalling removes exactly that entry.

Program files

On Windows the installer places the program, its README, licence, changelog and uninstaller in %LOCALAPPDATA%\Programs\NoiseCrypt (or Program Files if you chose an installation for all users), with a Start menu shortcut. On Linux the package installs /usr/bin/noisecrypt. On macOS the program is a single file that you place yourself.

03 / Network

What touches the network

NoiseCrypt sends nothing to BREIZHZION and contains no analytics, crash reporting or update check. Only two features use a network, and both only when you use them.

The interface, on your own machine only

noisecrypt gui (also what a double-click on the program opens) starts a small web server listening on 127.0.0.1, on a random port, which other computers cannot reach. It opens your default browser on an address that contains a random access token, created fresh at each launch and valid only until the interface stops. The browser then keeps that token in a session cookie, noisecrypt_token, restricted to that address. The files you drop into the page travel from the browser to NoiseCrypt on your machine, never further; the files it gives back are saved by your browser like any download. The page loads nothing from the Internet. Your browser may keep the address in its history, as it does for any page; the token in it is useless once the interface has stopped.

Decoding from an address, through yt-dlp

decode -url and the address field of the interface are optional and only work if yt-dlp, a separate program, is already installed: NoiseCrypt never downloads or installs it. When you use them, NoiseCrypt itself resolves the host name of the address (a DNS lookup) to refuse private network addresses, then runs yt-dlp, which connects to that address to download the video. That website therefore sees a request from your IP address, as it would if you watched the video in a browser. Nothing else is sent, and nothing goes to BREIZHZION. yt-dlp is run with --no-config, so your yt-dlp configuration files are ignored, but it may still keep its own cache (by default a yt-dlp folder under .cache in your home directory); that cache belongs to yt-dlp, and NoiseCrypt neither reads nor removes it.

FFmpeg, which NoiseCrypt uses to make and read videos, is also a separate program that must already be installed. It is only given local files.

04 / What others can see

What a container or a video reveals

The contents, file name and date are encrypted. A few things are not, and you should know them before you send a container to anyone:

  • A container encrypted to an identity carries, in clear, the fingerprint (SHA-256) of the recipient's public identity. Anyone who has the container and knows that public identity can tell who it is addressed to. A container encrypted with a passphrase carries no such fingerprint.
  • The size of a container or video gives an idea of the size of what is inside.
  • A NoiseCrypt video is recognisable as one. This is not steganography and offers no deniability.
  • Once you upload a video to a platform, that platform holds it, under its own terms, together with whatever it knows about your account. NoiseCrypt plays no part in that.

05 / Removing your data

What uninstalling removes, and what it keeps

Uninstalling on Windows removes the program files, the Start menu shortcut, the right-click and double-click entries and the Path entry. Removing the Linux package removes /usr/bin/noisecrypt.

Your identities are kept, on purpose

Uninstalling never deletes the .noisecrypt folder. Your private identity is the only way to open what has been encrypted to you, and losing it is irreversible, so it is not deleted as a side effect of a routine action. Your containers, videos and recovered files are kept as well.

To remove everything NoiseCrypt left behind, delete the .noisecrypt folder in your home directory (and any identity you created in a folder of your choice), the files you produced, and, if you want, yt-dlp's cache and your browser's history. Back up your identity first if you may ever need to open something encrypted to it.

06 / Third parties and contact

Who receives data

No one, from NoiseCrypt. BREIZHZION receives no data from the software, and no analytics, advertising or telemetry provider is involved. The only third parties the software ever reaches are the ones you point it at: the website behind an address you ask it to decode from, through yt-dlp.

Downloading NoiseCrypt (from GitHub, dl.breizhzion.com, apt.breizhzion.com or a package manager) is an ordinary download, and those servers see it like any other request. This policy covers the software once it is on your machine.

Questions about this policy: open an issue on GitHub, or write to contact@breizhzion.com. NoiseCrypt is published by BREIZHZION, a French non-profit association.

Version française

Politique de confidentialité

NoiseCrypt fonctionne entièrement sur votre ordinateur. Il n'a ni compte, ni serveur, ni télémétrie, ni rapport de plantage, ni vérification de mise à jour, et il n'envoie rien à BREIZHZION ni à personne. Cette version dit la même chose que la version anglaise ci-dessus. Mise à jour le 2026-10-24, valable à partir de NoiseCrypt 0.7.2.

Ce qui est traité

Le contenu des fichiers que vous chiffrez ou déchiffrez est lu en mémoire puis écrit à l'endroit demandé, sans être conservé ailleurs ni envoyé. Les phrases de passe sont saisies sans écho, ou lues dans le fichier ou la variable d'environnement que vous indiquez (-passphrase-file, -passphrase-env), ou tapées dans l'interface, et ne restent en mémoire que le temps de l'opération ; NoiseCrypt ne les écrit jamais sur le disque ni dans un journal, et ne les met jamais sur une ligne de commande. Dans l'interface, le navigateur ou le gestionnaire de mots de passe peut proposer de retenir une phrase de passe, comme sur toute page : cette copie, si vous l'acceptez, appartient au navigateur et non à NoiseCrypt. Les identités publiques des autres sont lues là où vous les donnez, sans être copiées. Le nom et la date d'un fichier chiffré sont rangés à l'intérieur du conteneur chiffré.

Ce qui est écrit sur le disque

Votre identité : deux fichiers dans un dossier .noisecrypt de votre dossier personnel (%USERPROFILE%\.noisecrypt sous Windows, ~/.noisecrypt sous macOS et Linux). identity.ncrykey est votre identité privée, chiffrée par votre phrase de passe (Argon2id) sauf si vous avez choisi de la stocker sans protection ; une identité créée par une ancienne version peut s'appeler identity, sans extension, et n'est jamais renommée. identity.ncrypub est votre identité publique, celle que l'on transmet, sans rien de secret. Le dossier n'est volontairement pas dans AppData, qu'un profil Windows joint à un domaine ou à Entra peut synchroniser vers un serveur. NOISECRYPT_HOME et NOISECRYPT_IDENTITY permettent de le déplacer.

Droits d'accès : 0700 pour le dossier et 0600 pour les fichiers sous macOS et Linux. Sous Windows, NoiseCrypt passe icacls sur le dossier et chaque fichier : l'héritage est coupé, et les groupes Administrateurs, SYSTEM et Utilisateurs sont retirés, seul votre compte garde l'accès. Cela empêche un autre compte ordinaire de lire votre clé, pas quelqu'un qui peut déjà agir en administrateur. Conséquence : un logiciel de sauvegarde qui tourne en SYSTEM peut ne pas lire ces fichiers, copiez donc votre identité vous-même en lieu sûr. keygen -out et l'entrée de clic droit Create a NoiseCrypt identity here écrivent les deux mêmes fichiers dans le dossier choisi, et appliquent la même restriction à ce dossier, pas seulement aux fichiers.

Les fichiers que vous demandez, à l'endroit indiqué ou à côté de leur source, jamais par-dessus un fichier existant sans -force : le conteneur .ncry de seal, la vidéo .mp4 de encode (produite par FFmpeg), le fichier retrouvé par open et decode dans le dossier courant (pour le clic droit, normalement celui du conteneur), et les vidéos d'essai de simulate -keep (<profil>-master.mp4, <profil>-h<hauteur>-crf<qualité>.mp4) dans le dossier indiqué.

Les fichiers temporaires, dans le dossier temporaire du système, à nom imprévisible, supprimés dès la fin de l'opération, y compris en cas d'échec : noisecrypt-dl-*, noisecrypt-in-*, noisecrypt-*.mp4, noisecrypt-simulate-* et multipart-*. Si NoiseCrypt est tué en pleine opération, l'un d'eux peut rester ; on peut le supprimer sans risque.

L'intégration à Windows, si vous gardez l'option de l'installateur (cochée par défaut, y compris en installation silencieuse) ou lancez noisecrypt shell register : des clés sous HKEY_CURRENT_USER\Software\Classes, pour votre seul compte (*\shell\NoiseCryptEncrypt, Directory\Background\shell\NoiseCryptIdentity, NoiseCrypt.Container, .ncry), qui ne contiennent que des libellés, une icône et le chemin du programme. noisecrypt shell unregister les retire. L'option d'ajout au Path y ajoute le dossier du programme, et la désinstallation retire exactement cette entrée.

Le programme : %LOCALAPPDATA%\Programs\NoiseCrypt sous Windows (ou Program Files pour une installation pour tous), avec un raccourci du menu Démarrer ; /usr/bin/noisecrypt sous Linux ; un fichier unique que vous placez vous-même sous macOS. Il n'y a ni fichier de réglages, ni historique, ni journal.

Le réseau

L'interface (noisecrypt gui, ou un double-clic sur le programme) écoute sur 127.0.0.1, sur un port au hasard, injoignable depuis un autre ordinateur. Elle s'ouvre dans votre navigateur avec un jeton aléatoire, recréé à chaque lancement et valable jusqu'à l'arrêt de l'interface, que le navigateur garde dans un cookie de session, noisecrypt_token. Les fichiers déposés dans la page ne vont que du navigateur à NoiseCrypt, sur votre machine ; ceux qu'il rend sont enregistrés par le navigateur comme tout téléchargement. La page ne charge rien depuis Internet. L'historique du navigateur peut garder l'adresse, dont le jeton ne sert plus à rien une fois l'interface arrêtée.

Le décodage depuis une adresse (decode -url, ou le champ d'adresse de l'interface) ne fonctionne que si yt-dlp, un programme distinct, est déjà installé : NoiseCrypt ne le télécharge ni ne l'installe jamais. NoiseCrypt résout lui-même le nom de l'hôte (une requête DNS) pour refuser les adresses de réseau privé, puis lance yt-dlp, qui se connecte à cette adresse pour télécharger la vidéo. Ce site voit donc une requête venant de votre adresse IP, comme si vous regardiez la vidéo dans un navigateur. Rien d'autre n'est envoyé, et rien ne va à BREIZHZION. yt-dlp est lancé avec --no-config, mais peut garder son propre cache (par défaut un dossier yt-dlp sous .cache dans votre dossier personnel), que NoiseCrypt ne lit ni ne supprime. FFmpeg, lui aussi distinct et à installer soi-même, ne reçoit que des fichiers locaux.

Ce qu'un conteneur ou une vidéo laisse voir

Le contenu, le nom et la date sont chiffrés. En revanche, un conteneur chiffré pour une identité porte en clair l'empreinte (SHA-256) de l'identité publique du destinataire : qui détient le conteneur et connaît cette identité sait à qui il est adressé, ce qui n'est pas le cas d'un conteneur chiffré par phrase de passe. La taille donne une idée de celle du contenu. Une vidéo NoiseCrypt se reconnaît comme telle : ce n'est pas de la stéganographie, et il n'y a aucune déniabilité. Une vidéo déposée sur une plateforme y est conservée selon ses conditions, avec ce qu'elle sait de votre compte, sans que NoiseCrypt y soit pour rien.

Désinstaller, et supprimer vos données

La désinstallation sous Windows retire le programme, le raccourci, les entrées de clic droit et de double-clic, et l'entrée du Path ; retirer le paquet Linux retire /usr/bin/noisecrypt. Elle ne supprime jamais le dossier .noisecrypt : votre identité privée est le seul moyen d'ouvrir ce qui vous a été chiffré, et sa perte est irréversible, donc elle n'est pas effacée par effet de bord d'un geste banal. Vos conteneurs, vidéos et fichiers retrouvés restent aussi. Pour tout retirer, supprimez le dossier .noisecrypt (et toute identité créée dans un dossier de votre choix), les fichiers produits, et si vous le souhaitez le cache de yt-dlp et l'historique du navigateur. Sauvegardez d'abord votre identité si vous pouvez encore avoir à ouvrir quelque chose qui lui a été chiffré.

Tiers et contact

Personne ne reçoit de données de NoiseCrypt : ni BREIZHZION, ni aucun service de mesure, de publicité ou de télémétrie. Les seuls tiers que le logiciel joint sont ceux que vous lui désignez, le site d'une adresse que vous lui demandez de décoder, par yt-dlp. Télécharger NoiseCrypt (GitHub, dl.breizhzion.com, apt.breizhzion.com ou un gestionnaire de paquets) est un téléchargement ordinaire, que ces serveurs voient comme toute autre requête. Questions : un ticket sur GitHub, ou contact@breizhzion.com. NoiseCrypt est publié par BREIZHZION, association loi 1901.
